# ordstat: k-th smallest value and inversion count

Code: `core/ordstat/ordstat.cpp` (contract in `core/ordstat/ordstat.h`). Tests: `tests/ordstat/ordstat_tests.cpp`. Reference: `tools/ordstat_ref.py`.

## Rule

- `select_kth_u32(a, n, k, out)`: the value that would sit at index k (0-based) if a[0 .. n) were sorted ascending, by unsigned comparison. Equal values count separately, so k = 0 is the minimum and k = n - 1 the maximum.
- `inversion_count_u32(a, n, scratch, scratch_words, out)`: the number of pairs i < j with a[i] > a[j] (strictly greater; equal values are not inversions), as a u64.
- Limit: n is at most `kMaxLen` = 2^20.
- Scratch need for inversions, in u32 words: 2 * n when n is above 1, else 0. It is computed in 64 bits. Scratch contents are unspecified afterwards, and this file does not assert any scratch value after a call.
- Failures leave `*out` untouched, and select leaves the array untouched on failure. After a successful select the order of the array is not specified and not asserted. Inversion count does not change the input.

Integer only: no allocation, no recursion, no mutable statics, no 128-bit types, no compiler-specific constructs. No aliasing claim is made.

## Method

- select: iterative three-way quickselect (Dijkstra partition). The pivot is the median of three elements picked from the current window by a local xorshift32 generator (a local variable, seeded with a constant, no static state). The window shrinks to the side that holds k, and the loop ends when k falls in the equal group.
- inversions: the input is copied into the first n scratch words and merged by an iterative bottom-up merge using the second n words. On equal values the left run is taken first, so equal values add no count. When a value is taken from the right run, `mid - i` is added.

Expected time of select is linear. The header promises linear time only for the three structured inputs: sorted, reversed and all-equal. Organ-pipe and 3-value inputs are extra evidence, not a promise. There is no worst-case guarantee: an adversarial input can make select slower. Inversion counting is O(n log n).

## Check order

select: NullArgument first (`out` always, `a` only while n is above 0), then TooLarge (n above 2^20), then OutOfRange (k >= n, so every k when n is 0).

inversions: NullArgument first (`out` always, `a` only while n is above 0, `scratch` only while the need is above 0), then TooLarge, then ScratchTooSmall (`scratch_words` below the need).

## Decisions

These readings were confirmed by the maintainer through the coordinating agent: 0-based k; the check orders above; the 64-bit need; no assertion of scratch contents; no assertion of array order after select; no aliasing claim; the iterative quickselect and bottom-up merge; the 2^20 cases with completion as the evidence (no wall-clock or step-count assertions).

## Tests

Expected values come from `tools/ordstat_ref.py`, an independent Python programme (sorted list for select; bisect insertion, brute force over all pairs and closed formulas for inversions), with golden digests. Success tests use buffers of exactly the declared length under ASan; tiny or null buffers appear only for NullArgument, TooLarge, OutOfRange and ScratchTooSmall failures and for length-0 inputs.

- Reference rows: all small arrays over {0,1,2}, random arrays, and longer arrays, for both functions.
- Every k on small arrays: the result equals the sorted value, and the multiset is unchanged (exact sorted comparison on small arrays).
- 2^20 values: real 2^20 buffers for sorted, reversed and all-equal inputs at the first, middle and last rank; organ-pipe and 3-value patterns as extra evidence. At this size the multiset check uses a fingerprint (a sum of a 64-bit mix of each value plus the plain sum), not an exact sorted comparison, so it is strong evidence but not a proof of equality.
- Inversions at 2^20 against closed formulas, including the count 549755289600 for the reversed input, which needs 64 bits.
- Hand-checked values, argument rules, check order and the exact-need scratch boundary.

Time is not asserted. A quadratic method would need about 10^12 steps at 2^20, so finishing is the evidence.

## Local run

LOCAL only, not CI: g++ -std=c++17 -O1, ASan + UBSan, with -Wall -Wextra -Wpedantic -Wconversion -Wshadow, no warnings and no runtime errors: 8 test cases, 116466 assertions, all passed. No MSVC, Clang, Windows or Android result was seen; Windows is covered by CI only.

## Not run

- Exhaustive inputs beyond the small ranges.
- Adversarial pivot inputs, and any worst-case timing claim.
- MSVC, Clang, Windows, Android.

## Mutation

111 source mutants (generated by a script that is not committed), built with `-fno-sanitize-recover=all`, harness timeout 10 s per mutant. 58 were killed by an assertion, 24 by a crash only, 9 stopped by timeout, 20 were not killed.

### Crash-only kills (24)

select: no null check on out; no null check on a; a null for n above 1; range check `>` instead of `>=`; no range check; `lt` start value changed; swap on the less branch without `i++`; `k<lt` using `<=`; `hi` set to `lt-2`.

inversions: no null check on out; need for n above 1 changed (two forms: `n` instead of `2n`, and the n > 1 test); no scratch null check (two forms: none, and no need test); scratch size check `-1`; `n<1` for small n; mid clamp; end clamp; taking right without `j++`; taking left without `i++`; rest-left `<=`; merge `i<=`; merge `or`; merge `j<=`.

### Timeouts (9), listed apart from assertion kills

A timeout is not counted as an assertion kill. Each was inspected, and the class below says what the inspection or timing showed.

- No termination (inspected; also confirmed by hanging for 3 s on a 40-element input in a separate run): `sel pick idx` (pivot taken outside the window), `sel less <=` (all-equal input), `sel swap gt no gt--`, `sel eq no i++`, `sel no break` (all-equal input).
- Quadratic time (inspected: each round removes one element): `sel pick lo`, `sel pick hi`, `sel rng zero` (xorshift of 0 stays 0, same as pick lo), `sel pivot const`. Doubled-size timing on sorted and reversed inputs at -O1, no ASan, local: about 76, 306 and 1226 ms at n = 16384, 32768 and 65536 for the worst case, near 4x per doubling; the real code takes 0.03 to 0.12 ms there. Timing is local evidence only and is not part of the tests.

### Not killed (20) and why

Pivot-quality mutants change only the expected speed, since the pivot is always a value from the window, so the selected value is the same: median-of-three variants (x<y first, y<z, x<z inner, x<z outer, y<z last, always x, max, min), `sel pick last`, `sel rng 13`, `sel rng no shift`, `sel pick count`, `sel pivot use`, `sel pivot min`, `sel span`. The tests do not measure speed, by decision, so these survive. They are result-equivalent, not time-equivalent.

- `sel loop <=`: result-equivalent. When lo equals hi, k lies in the equal group and the loop breaks.
- `sel hi lt`, `sel k>gt >=`, `sel lo gt`: they keep k inside the window, so the value is the same whenever the loop ends. On some pivot choices they fail to shrink the window. With the random pivots they end with probability 1 but have no worst-case bound; they are reported as time-only, and not proven equivalent in termination.
- `inv width <=`: equivalent. The extra pass at width >= n has start 0, mid = end = n, adds no count and only swaps the buffers.

None of the 20 is non-equivalent in result.
