# Renderer (Section 7)

> Normative document of the Lumora Master Plan. Section numbers are stable IDs shared by all files and are not contiguous inside one file. Read `LUMORA_MASTER.md` first.

## 7. Renderer

Built on the RHI, shared by editor preview and phone.

- **Scene traversal → draw lists.** The scene graph is traversed once per frame into sorted draw lists (opaque front-to-back, transparent back-to-back), culled by frustum.
- **Cameras:** perspective/orthographic; the wallpaper's virtual camera with parallax offsets from sensors/touch is a camera controller, not a renderer special case.
- **Lighting & materials:** PBR metallic-roughness (matching glTF), image-based lighting from a baked BRDF LUT + prefiltered environment map, up to N dynamic lights (N chosen by quality tier: 4 on low, 8 on high), directional shadows via a single cascaded or simple projected shadow map (quality-gated).
- **Per-tier pass budget (Mali-G76 reality):** the feature list above is not simultaneously affordable on the low tier at 1080x2400. The low tier (Realme 6 profile) defaults to: no shadow map, no bloom, 1-2 dynamic lights, render scale below 1.0 for 3D scenes; offscreen intermediates use R11G11B10F (a queried capability on GLES, `EXT_color_buffer_float`, with an LDR fallback) or an LDR path; tone mapping, grading LUT and FXAA are folded into one final full-screen pass; MSAA with in-tile resolve (`EXT_multisampled_render_to_texture` on GLES) is preferred over FXAA where available. Scenes are gated as shippable samples per workload class (Section 16.3), not by one global 60 fps rule.
- **Forward+ is overkill here**: clustered/forward-plus is explicitly rejected for v1 (tile GPU, few lights). Simple forward with light culling by distance is the plan.
- **Post-processing stack (per-scene opt-in):** bloom, tone mapping (ACES), vignette, color grading LUT, FXAA. Rendered at render-scale resolution (D14: quality settings control this).
- **2D support:** billboard/sprite layers and a full 2D layer mode (parallax stacks of images, the classic live-wallpaper style) rendered through the same pipeline.
- **Particles:** GPU-simulated where the backend supports compute (Vulkan always; GLES 3.2 via compute; D3D12 always), CPU fallback otherwise. Emitter properties editable in the editor; script-controllable. On the Mali-G76 the CPU fallback is the default above a measured particle-count threshold, since compute and graphics serialize on a tiler anyway.
- **Video textures** use a backend-neutral video-frame abstraction: the core sees a `VideoTexture` with acquire/release of the latest frame, frame timestamps, producer-consumer synchronization (binary fences / frame-slot counters everywhere; timeline semaphores only as an optional Vulkan capability; `glFenceSync` latch on GLES; shared fences on D3D12), ownership/lifetime rules, color conversion, and sampling restrictions. `SurfaceTexture` is GL-only and is not the Vulkan path. Android decodes through MediaCodec: on GLES into a `SurfaceTexture` sampled as `GL_TEXTURE_EXTERNAL_OES`; on Vulkan into an `AImageReader` created with GPU-sampled usage, and the frame's `AHardwareBuffer` is imported via `VK_ANDROID_external_memory_android_hardware_buffer` with an immutable YCbCr conversion sampler baked into the binding layout (Section 6.2) and a queue-family-foreign ownership transfer, where the driver supports it. The GLES sampling uses the special external-sampler shader variant from the shader contract (6.2.1). Windows uses Media Foundation into a shared texture. Where external import is unavailable, the fallback is a CPU YUV-to-RGBA upload into a regular `Texture2D` at a capped rate (and cutting v1 video to the CPU path with zero-copy as an optional capability is the documented fallback if the import path proves unreliable). YUV conversion honors the video's primaries/transfer/matrix/range metadata (BT.601/BT.709) with a documented default when metadata is missing. Decoder-to-render-thread synchronization, frame-drop policy, seek/loop rules, pause and decoder release on wallpaper visibility, and per-device codec/resolution limits are specified in `docs/rhi-spec.md`; concurrent video count and resolution are budget-capped. Opt-in per material, with editor warnings about cost on the Mali-G76.
- **Text rendering:** dynamic text via a font atlas (useful for clocks, battery readouts in scenes); Arabic shaping and bidi through the Lumora text engine (Section 13) so Arabic text in scenes renders correctly.

### 7.1 Rendering equivalence, 2D/3D composition, and animation

- **Color management:** one linear-workflow contract for all backends: sRGB textures decoded on sampling, linear lighting, ACES tone mapping, sRGB output; explicit texture color-space metadata in the package, premultiplied-alpha convention for 2D layers, and pinned depth/projection, handedness, winding, and UV-origin conventions per backend. Golden-image comparisons are exact on the software reference path and perceptual/region-tolerant across hardware vendors (Section 16.1). **v1 is SDR-only:** the swapchain is sRGB on every platform and HDR output is a post-v1 candidate; an sRGB swapchain is a queried capability, not an assumption - on GLES it needs `EGL_KHR_gl_colorspace`, and where it is absent the renderer renders linear to an offscreen target and does a manual sRGB encode in the final pass, with a golden test for both paths; video primaries/transfer/range are converted into the SDR pipeline per the video rules in Section 7. Color-conversion paths get their own golden tests.
- **2D/3D composition:** 2D layers are scene-graph nodes in ordered layer groups (background → 3D world → foreground → overlay), with defined screen-space units, parallax factors, camera relationship, blend modes, and touch mapping from screen coordinates into the layer's space. Post-processing applies per layer group as configured.
- **Animation:** clips are keyframed property curves (editor-authored) and glTF skeletal clips; v1 supports clip cross-fading and Lua-driven clip control (`play/stop/blend/speed`), animation events into Lua, and GPU skinning with a CPU fallback below the capability tier. Blend trees, root motion, and retargeting are explicitly **post-v1** (labeled, not promised).
