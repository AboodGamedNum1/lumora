# Physics and audio engines (Section 12)

> Normative document of the Lumora Master Plan. Section numbers are stable IDs shared by all files and are not contiguous inside one file. Read `LUMORA_MASTER.md` first.

## 12. Physics & audio engines

- **Physics: Jolt Physics** (MIT license, compatible with Apache-2.0 distribution; modern, fast, actively maintained, requires C++17, proven on mobile). Convex decomposition of concave meshes at import uses a dedicated library (VHACD, BSD license) added to Section 14.1 as an import-time-only tool dependency - Jolt builds convex hulls but does not decompose concave meshes into multiple hulls. Integrated behind a thin core wrapper so a swap stays possible. Features exposed: rigid bodies (static/dynamic/kinematic), box/sphere/capsule/convex colliders, constraints (hinge/spring/distance), raycasts for scripts, gravity control. Scenes opt in per-node; a scene with no physics bodies pays near-zero cost. **Limits and honesty:** fixed timestep with per-tier body/constraint caps, collision layers and filtering, sleeping, and no mesh colliders on dynamic concave shapes (static only; convex decomposition offered at import). Physics runs at the fixed simulation rate on the logic thread; results sync to scene transforms at frame boundaries; physics events dispatch into Lua. **Determinism:** Jolt is deterministic on the same binary, and Jolt documents a `CROSS_PLATFORM_DETERMINISTIC` option (about 8% slower; needs strict floating-point settings, no FMA contraction and identical defines). Cross-device determinism is therefore possible but **not promised in v1**; whether to enable it is decided at M8 from measured cost, and the physics golden scene compares same-binary runs only until then. **Untrusted inputs:** every Lua-to-Jolt value is sanitized (finite, clamped ranges for velocity, mass and sizes), convex hull vertices and mesh triangles are capped at import and at load, baked VHACD output is validated, and a non-finite state triggers a recoverable physics reset (Jolt asserts are compiled out in release builds, so bad input would otherwise be silent). Maximum bodies, pairs and constraints are fixed per scene load at `PhysicsSystem` init, not dynamic.
- **Audio playback: Oboe** (Google's Apache-2.0 C++ library) on Android, miniaudio on Windows and Linux for editor audition. Formats: OGG/Opus primary. **Decoder gap closed:** miniaudio decodes only WAV/FLAC/MP3 built in and Oboe is playback-only (PCM), so the manifest gains a real OGG/Opus decode path: **libogg + libopusfile** (opusfile sits on libogg and libopus; libopus alone decodes packets and does not parse Ogg) for Ogg Opus and **libvorbisfile** (libogg + libvorbis) for Ogg Vorbis, BSD licenses, behind the audio interface on all platforms (via NDK on Android; MediaExtractor is the documented alternative). **stb_vorbis is dropped:** the security reviewer reports an open heap overflow (stb issue 1947) and several CVEs including CVE-2026-5317 (NVD page cited, not re-fetched). If any stb header stays (stb_image has similar open reports), it is built under ASan/UBSan fuzzing and decodes in a size-limited context. All three Ogg libraries are fuzzed at the demux boundary. Audio in wallpapers is opt-in per scene and muted by a global switch, because a wallpaper must never surprise the user with sound. **Lifecycle rules:** wallpaper audio never starts without an explicit user choice; audio focus is honored (duck/stop on calls, alarms, and other apps' media); playback pauses when the wallpaper is hidden; output-route changes (headphones/Bluetooth) reconfigure the stream; simultaneous-voice caps, loop/stream policy, and per-scene plus global volume controls.
- **Audio reactivity:** FFT/loudness analysis feeding the scripting API (Section 9.3, three distinct capabilities with explicit status returns).
