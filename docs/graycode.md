# graycode: binary Gray codes and the k-ary reflected Gray code

Code: `core/graycode/graycode.cpp` (contract in `core/graycode/graycode.h`). Tests: `tests/graycode/graycode_tests.cpp`. Reference: `tools/graycode_ref.py`. Evidence label: unit tests only.

## Rule

- `gray_encode(x) = x ^ (x >> 1)` and `gray_decode` is its inverse for every u64. Both are total (no checks).
- The k-ary reflected code has base k (2 to 16) and n digits (1 to 16), digit i in bits 4i..4i+3, digit n - 1 the slowest. Ranks 0 to k^n - 1; the code of rank 0 is all zero digits; consecutive codes differ in one digit by exactly 1. The top digit d runs 0 to k - 1 and the lower digits follow the (n - 1)-digit sequence forward when d is even and backward when d is odd.
- `kgray_count` gives k^n, or Overflow when it is 2^64 or more (only (16, 16)). `kgray_unrank`, `kgray_rank` and `kgray_next` never give Overflow. For (16, 16) every u64 is a valid code and a valid rank.
- Check order, all four k-ary functions: a null `out` is NullArgument; then k outside 2..16 or n outside 1..16 is BadArgument; then (rank and next) a code with a digit of k or more, or with a bit at 4n or above, is BadCode (before NoNext); then (unrank) a rank of k^n or more is RankTooLarge; then (next) the last code is NoNext. Nothing is written to `*out` on a failure.
- Pure integer. No heap, arrays, tables, recursion, mutable statics, 128-bit types, builtins or intrinsics in the implementation. Cost: at most 16 loop steps per k-ary call, each with one division or multiplication; the binary functions take 1 and 6 shift-xor steps.

## Method

- `gray_decode` is the prefix xor `g ^ g >> 1 ^ g >> 2 ...`, done by the shifts 1, 2, 4, 8, 16, 32 (the largest shift is 32; no shift by 64).
- `kgray_unrank`: pw = k^(n-1) (at most 16^15 = 2^60). The top digit is rank / pw and must be below k (that is exactly rank < k^n, so k^n is never formed). Then for each digit from the top: d = r / pw, r -= d pw, the digit is d, and when d is odd the remainder is reflected (r = pw - 1 - r); then pw /= k.
- `kgray_rank`: from the top, with `odd` the parity of the number of odd code digits above: the rank digit is g when `odd` is 0 and k - 1 - g otherwise; rank = rank * k + digit; `odd ^= g & 1`.
- `kgray_next`: digit i runs up when the number of odd digits above it is even and down otherwise. The next code moves the lowest digit that is not at the end of its run (up: below k - 1; down: above 0) by exactly 1. If no digit can move the code is the last. The parity above digit i is the total parity minus the digits up to i, so one pass computes it.
- `kgray_count`: a loop of n multiplications; before each multiplication p > max / k means Overflow.
- Validity: no bit at 4n or above (the shift 4n is taken only for n below 16, so never by 64) and every digit below k.

## Proofs

**Rank is the inverse of unrank.** Let R_n(c) be the rank in the n-digit sequence S_n. By the definition, for a code with top digit d and lower part c', R_n(c) = d pw + R_(n-1)(c') for even d and d pw + (pw - 1 - R_(n-1)(c')) for odd d, where pw = k^(n-1). The number pw - 1 has the digit k - 1 in every position, so pw - 1 - x is the digit-wise complement (every digit x_i becomes k - 1 - x_i) with no borrow. Induction on n: the rank digits of c' are x_i = g_i or k - 1 - g_i according to the parity of the odd digits above i inside c'; for odd d every x_i is complemented, which flips that selection, and so the selection for the n-digit code uses the parity of the odd digits above i inside c including d. That is the rule the code uses. Unrank is the same recursion read from the top: the top digit is the quotient, and the remainder is taken forward or reflected.

**Next.** Say a digit is feasible when it can move one step in its direction (direction up when an even number of odd digits are above it). Claim A: the successor of a code in S_n changes the lowest feasible digit by one step in its direction, and a code with no feasible digit is the last. Claim B: the predecessor changes the lowest digit that can move one step in the opposite direction, and a code with no such digit is the first. Induction on n. For n = 1 the sequence is 0..k-1 and the only digit runs up. For the step take the code (d, c'). If d is even, the block of d follows S_(n-1) forward, and the directions of the lower digits are those they have in c' alone (d does not change the parity). The successor inside the block is the successor of c' (claim A for n - 1). If c' is the last code of S_(n-1) then no lower digit is feasible and the next block (d + 1, odd) starts at the last code of S_(n-1), so only the top digit moves up, which is the lowest feasible digit (the parity above the top digit is 0). If d is odd, the block runs S_(n-1) backward, the successor of (d, c') in the block is the predecessor of c' in S_(n-1), which by claim B moves the lowest digit that can move opposite to the (n - 1)-directions, and in the n-digit code every direction is flipped by the odd d, so that is the lowest feasible digit. If c' is the first code (all zero digits) the next block starts with the same lower digits and the top digit moves up; the lower zero digits are directed down and cannot move. Claim B is the same argument with the blocks and directions read the other way. A code that is not last has a successor, which by claim A moves a feasible digit, so a code with no feasible digit is the last.

**One digit by exactly 1.** Claim A moves one digit by one step, never modulo k.

**No intermediate reaches 2^64 for any k and n.**
- unrank: pw <= 16^15 = 2^60 and is divided by k at every step. The first division is `rank / pw` with rank at most 2^64 - 1 (valid for every u64, since the top digit is below k = 16 when n = 16 and k^n = 2^64). Then d <= k - 1 <= 15 (at the first digit by the RankTooLarge check, afterwards because r < pw), d pw <= r, and r - d pw < pw. The reflection pw - 1 - r is at most pw - 1 and never wraps because r < pw. The code takes d << 4(i - 1) with 4(i - 1) <= 60.
- rank: after the top m digits the value is floor(R / k^(n - m)) where R is the final rank, so every partial value is at most R < k^n <= 2^64, and `rank * k + digit` is never above 2^64 - 1. The digit is at most 15 (k - 1 - g with g <= k - 1).
- next: the shifts are 4i <= 60; adding 1 to a digit below k - 1 <= 14 stays inside its nibble, and subtracting 1 from a digit above 0 does not borrow.
- count: `p > max / k` before `p *= k` means the product p k is at most max. For (16, 16) p is 2^60 after 15 steps and 2^60 > (2^64 - 1) / 16 = 2^60 - 1, so Overflow. For every other (k, n) the product never exceeds max (tested for all 240 pairs).
- valid_code: the shift 4n is taken only for n < 16 (at most 60), and the digit shifts are 4i with i < n <= 16 (at most 60).

## Tests

Expected values come from the header's examples, from test-only oracles of a different method than the library, and from FNV-1a 64-bit digests made by `tools/graycode_ref.py` (Python standard library only, no code shared with the library). The oracles in the test: the code table built level by level from the header's definition with arrays (every (k, n) with k^n up to 65536); a bit-loop Gray decode; k^n by squaring with an overflow test; validity by taking nibbles with division; the one-digit-by-exactly-1 test digit by digit; and popcount of encode(x) xor encode(x + 1) equal to 1.

**The reference and how its large-n method differs from the library.** `graycode_ref.py` builds the sequence literally from the header's definition: seq_n = for d in 0..k-1: d followed by seq_(n-1) forward (d even) or backward (d odd), as explicit lists. Every walk digest (all k^n up to 2^22) is made from these lists, so no formula is involved there. For the larger sizes it uses the same definition as a recursion on the index: unrank_rec(n, r) takes the block d = r // k^(n-1), reflects the index of the remainder when d is odd, and recurses; rank_rec is its structural inverse; the successor is unrank(rank + 1) (the library does not do that). The library uses neither lists nor recursion: it uses an iterative rule on the parity of the odd digits above each digit, a closed form for rank, and a direction rule for next. So the reference is a recursive formulation of the definition and the library is an iterative formulation of a derived rule; the reference is not a Python port of the library. The two meet at the recursion's index reflection, and `check` ties the recursion to the explicit lists for every (k, n) with k^n up to 2^16 (every rank) and sampled ranks up to 2^20, tests adjacency on the explicit lists up to 2^20, the header examples, 200 sampled ranks for every (k, n) (round trip and one digit by exactly 1 against rank + 1), and encode / decode inverses.

Local runtimes (gcc 11.4.0, `-O1`, ASan + UBSan, one core; base 77d66c6; the whole binary has 15 test cases and 27 assertions and takes about 4 s; every case is far under 30 s). Cases are declared cheap first:

For each: decode(encode(x)) = x, encode(decode(x)) = x, the bit-loop decode agrees, and encode(x) and encode(x + 1) differ in one bit.

## Mutation testing

420 source mutants of `core/graycode/graycode.cpp` (script outside the repository, grouped by function: the power loop, `valid_code`, `bad_args`, encode, decode, count, unrank, rank, next; shift-width, check-order, wrong-digit, parity and reflection-direction mutants among them), each built with ASan + UBSan against the final tests (md5 `becaaf47589d778350945bfa0d684fb1`; the library md5 is `9d15a05b0cd6c349157498b6d6d682ee`; the reference md5 is `f30dda3fda99d3c643b9985c9a81ba5c`; none was edited after the run), abort after the first failure, declaration order. The first pass ran three builds at a time on one core with a 40 s limit. Every survivor, the timeout and the cost mutants were rerun alone; the survivors alone with a 40 s limit and the cost mutants timed alone.

- 391 killed: 337 by a failed assertion and 54 by an abnormal end (a sanitizer abort or a crash). This count includes `cm_dec_rep`, a cost-style mutant whose extra statement also changed the value.
- 1 did not compile (`u_or8`), so it is not a mutant of the program and is not counted as a kill.
- 21 survivors, each also surviving alone, each equivalent:
  - `d_rev` (the six decode shifts in the reverse order): each step is the map x -> x ^ (x >> s), these maps commute, so the composition is the same.
  - `c_ov0`, `c_ov2`, `c_ov3`, `c_ov4`, `c_ov6`, `c_ov7` (other forms of the overflow test in `kgray_count`): the domain of the function is finite after the argument check (k = 2..16, n = 1..16), and the test compares the result of every one of the 240 pairs with the squaring oracle and the digest, so a mutant that survives gives the same results on the whole domain.
  - `u_loop2` and `r_loop2` (`i >= 1` for `i > 0`): the same for unsigned i.
  - `u_d6` (`r / pw % k`): r / pw is below k at every step. `r_sel9` (`(k - 1 - g) % k`): the value is below k. `r_dig7` and `x_g4` (the digit taken modulo k): the digit is below k after the validity check.
  - `u_sub0` (`r %= pw` for `r -= d * pw`): with d = r / pw, r - d pw = r mod pw. `u_ref8` (`pw - 1 - r % pw`): r < pw at that point.
  - `u_or0` and `u_or1` (`+=` and `^=` for `|=` on the code): the bits written are disjoint (each digit goes to its own nibble and d < 16).
  - `u_order_rtl` (`&& out != nullptr` added to the RankTooLarge test): `out` is not null there.
  - `x_dir4` (`(above & 1) == 0 && g < k`): `above` is 0 or 1 and g < k for a valid code; when the test fails for g = k - 1 the original also does not move the digit and does not reach the down branch.
  - `x_down3` (`g > 0 && g < k`) and `x_down7` (`g > 0 && above == 1 && i < n`): g < k, above is 1 in that branch and i < n in the loop.
- 6 cost mutants (the values are right, only the time grows; kept apart from the kills and the survivors; no test can detect them because the repository forbids timing assertions). Observed, whole suite alone, one core, with a 14 s limit: `cm_pow_rep` (400 extra writes in `power`) passes in 11 s; `cm_count_rep` 3 s; `cm_unrank_rep` (40 extra `power` calls) 5 s; `cm_rank_rep` 4 s; `cm_next_rep` (40 extra `valid_code` calls in next) 12 s; `cm_unrank_slow` (the multiple subtracted one pw at a time) 5 s. The unmutated binary takes about 4 s. One more, `cm_valid_rep` (400 extra digit scans in `valid_code`), did not finish in 100 s alone and was stopped (Catch2 prints the SIGTERM as a failure; that is the stop, not a kill).
- No mutant needed the loop probe: no non-cost mutant timed out.

## Not run

Other builds than the local gcc 11.4 ASan + UBSan, MSVC, Clang, Windows, Android, any timing assertion, and a mutant run on shuffled case order. The walks cover every code for k^n up to 2^22 only; for the larger sizes the checks are the edge ranks, the block boundaries and the seeded samples above (no whole walk). Aliasing is not applicable (one output).
