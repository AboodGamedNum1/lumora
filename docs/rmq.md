# rmq: range minimum queries with a sparse table

Code: `core/rmq/rmq.cpp` (contract in `core/rmq/rmq.h`). Tests: `tests/rmq/rmq_tests.cpp`. Reference: `tools/rmq_ref.py`.

## Rule

- `rmq_table_words(n, out)`: `*out` = n * (floor(log2 n) + 1) u32 words for n above 0, else 0. The need is computed in 64 bits; with n at most `kMaxLen` = 65536 the largest value is 65536 * 17 = 1114112.
- `rmq_build(a, n, table, table_words)`: builds the table for a[0 .. n) in caller storage. The table contents are unspecified and are used only through `rmq_query`. The array must not change between the build and the queries, and a query on a table that was never built is not tested.
- `rmq_query(a, n, table, table_words, l, r, out_index)`: the index of the smallest value (unsigned comparison) in a[l .. r], both ends included. When several positions hold that value, the leftmost one.
- Failures: the table (build) and `*out_index` (query) are left untouched; `*out_words` is not written when `rmq_table_words` fails. A build with n = 0 succeeds and writes nothing.

Integer only: no allocation, no recursion, no mutable statics, no 128-bit types. No aliasing claim is made.

## Method

Row k of the table sits at table[k * n .. k * n + n) and holds, for every start i with i + 2^k <= n, the index of the leftmost smallest value of a[i .. i + 2^k). Row 0 is the identity; row k is built from two entries of row k - 1, taking the left one when the values are equal. A query takes k = floor(log2(r - l + 1)), looks at the entries for l and for r + 1 - 2^k, and takes the left one when the values are equal. If both windows have the same minimum, the left entry is the leftmost position overall, because the left window starts first. The `floor(log2)` is a loop. The header's remark that a query reads at most two table rows is a design hint and is not asserted.

## Check order

- `rmq_table_words`: NullArgument (`out_words`), then TooLarge (n above 65536).
- `rmq_build`: NullArgument (`a` and `table`, only while n is above 0), TooLarge, ScratchTooSmall (`table_words` below the need), then Ok. n = 0 with zero words is Ok.
- `rmq_query`: NullArgument (`a`, `table` and `out_index`, always, also when n is 0), TooLarge, ScratchTooSmall, then OutOfRange (l above r, or r not below n, so every query when n is 0).

## Decisions

These readings were confirmed by the maintainer through the coordinating agent: the 64-bit table size formula, the limits, the closed range [l, r] with the empty/inverted rule, the n = 0 rules, the leftmost tie-break, the check orders, failures leaving outputs untouched, and the table-too-small handling. The array must not change between build and queries; no test queries an unbuilt table; no test asserts table contents after a build or any word beyond the need in a larger table.

## Tests

Expected values come from `tools/rmq_ref.py`, an independent programme that builds no table: it takes the minimum of the slice and the first position of that value, cross-checked by a strict-less scan. Table sizes come from n * bit_length(n). Success tests use a table buffer of exactly the declared length under ASan; tiny or null buffers appear only for NullArgument, TooLarge, ScratchTooSmall and OutOfRange failures and for length-0 inputs. Oversized cases (65537 and 4294967295) use tiny storage that is never read; a query still passes non-null `a`, `table` and `out_index` there.

- Table size formula at 25 sizes, including the powers of two and their neighbours and 65536.
- Exhaustive: every array over {0,1,2} with n = 1 to 6, every range.
- 300 random arrays (lengths 1 to 399; small, full 32-bit and near 2^32 values) with sampled ranges.
- n = 65536 on six structured inputs (sorted, reversed, all equal, repeated minima, pseudo-random, repeated minima near 2^32). Maximum-size queries are sampled (1548 ranges: ends, lengths around each power of two, random), not exhaustive.
- A golden digest of every answer, tables built over two different fills (the answers must not depend on the initial contents).
- Hand cases (ties, unsigned order, n = 1), argument rules, check order and empty-array queries.

The constant-time promise is not measured.

## Local run

LOCAL only, not CI: g++ -std=c++17 -O1, ASan + UBSan, -Wall -Wextra -Wpedantic -Wconversion -Wshadow, no warnings and no runtime errors: 12 test cases, 96988 assertions, all passed. No MSVC, Clang, Windows or Android result was seen; Windows is covered by CI only.

## Not run

- Exhaustive queries at n = 65536, and exhaustive arrays beyond n = 6 over three values.
- Any timing or step-count check.
- MSVC, Clang, Windows, Android.

## Mutation

75 source mutants (generated by a script that is not committed), each built with `-fno-sanitize-recover=all`, harness timeout 10 s. 61 were killed by an assertion, 7 by a crash only, 0 stopped by timeout, 7 were not killed.

### Crash-only kills (7)

table size without the `+ 1`; `rmq_table_words` without the null check on `out_words`; build without the null check on `table`; build row 0 off by one; query with `r > n` instead of `r >= n`; query without any check on `r`; query reading row k + 1.

### Timeouts (0)

No mutant timed out, so no non-termination or slow-time kill is claimed.

### Not killed (7), none non-equivalent in result

- `need no n0` (the n = 0 return in the size function removed): for n = 0 the log loop gives 0, so the size is 0 * 1 = 0. Equivalent.
- `need 32-bit`, `build scratch 32-bit`, `query scratch 32-bit` (32-bit arithmetic or compare instead of 64-bit): they are reached only after the TooLarge check, so n is at most 65536 and the need is at most 1114112, which fits. Equivalent for every reachable input.
- `build no n0 return` (the early return for n = 0 removed): for n = 0 the loops do not run, so nothing is written. Equivalent.
- `build loop extra` (one extra entry per row): the extra write goes to row k at index n - 2^k + 1, which is still inside that row, and it reads only entries inside the table and valid indices. A query never reads an entry whose window would pass the end of the array, and tests do not assert table contents after a build, by decision. Equivalent in every observable result; it changes only unspecified table words inside the needed size.
- `query len +0` (floor(log2(r - l)) instead of floor(log2(r - l + 1))): the two differ only when the length is a power of two, where the query then uses two adjacent half windows that together cover the range exactly, and the left one wins ties. Equivalent in result.
